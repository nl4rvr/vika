# Вика — цикл и мигрени

Личное PWA-приложение для отслеживания менструального цикла и мигреней.
Без серверов, без рекламы, без чужих глаз: данные лежат в браузере, а при желании — в **вашем**
Firebase-проекте.

```
┌──────────────────────────────────────────────┐
│  Сегодня   ·   Цикл   ·   Мигрени            │
│                                              │
│  кольцо дня цикла, фаза, прогноз, зачатие    │
│  календарь с месячными/овуляцией/мигренями   │
│  дневник мигреней с препаратами и заметками  │
│  557 советов по 4 фазам цикла                │
└──────────────────────────────────────────────┘
```

## 1. Что внутри

| Файл | Назначение |
|---|---|
| `index.html` | Разметка, SVG-иконки, экран PIN-кода, шторка |
| `styles.css` | Вся визуальная система: soft bento, стекло, пастель, анимации |
| `app.js` | Логика интерфейса, экраны, шторки, PIN, синхронизация |
| `js/dates.js` | Работа с датами (локальные даты, без UTC-сюрпризов) |
| `js/cycle.js` | Движок цикла: статистика, фазы, прогноз, карта дней |
| `js/tips.js` | Библиотека рекомендаций: выбор на день, фильтры |
| `js/store.js` | Хранилище, миграции, PIN, экспорт/импорт, слияние |
| `js/firebase.js` | Конфиг Firebase + вход и синхронизация (SDK грузится только при наличии конфига) |
| `js/pwa.js` | Версия кэша, список файлов оболочки, предзагрузка кэша |
| `data/tips/*.js` | 557 советов по фазам: менструация, фолликулярная, овуляция, лютеиновая |
| `manifest.json` | PWA-манифест (иконки, standalone, shortcuts) |
| `sw.js` | Service worker: офлайн-кэш, стратегии кэширования |
| `icons/` | Иконки 192/512, maskable, apple-touch-icon, favicon |
| `tools/` | Вспомогательное для разработки: локальный сервер, генератор иконок, превью экранов (деплой не нужен) |
| `.nojekyll` | Чтобы GitHub Pages не обрабатывал файлы через Jekyll |

Стек: **HTML5 + CSS3 + Vanilla JS (ES-модули)**, без сборки и npm.
Firebase подключается только если вы вставили конфиг — иначе приложение полностью локальное
и даже не грузит сторонние скрипты.

## 2. Локальный запуск (2 минуты)

ES-модули не работают по `file://`, поэтому нужен любой локальный сервер.

**Вариант А — Python (если установлен):**

```bash
cd путь/к/проекту
python -m http.server 8080
```

**Вариант Б — Node.js:**

```bash
npx serve -l 8080
```

**Вариант В — Windows без ничего:** в комплекте есть мини-сервер

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\serve.ps1 -Port 8080 -Root .
```

Откройте <http://localhost:8080>. Готово — можно отмечать цикл.

## 3. Firebase за 5 минут (необязательно, но полезно)

> **В этом проекте Firebase уже подключён.** Конфиг лежит в `js/firebase.js` (проект
> `vika-cycle`), Email/Password включён, Firestore создан в `europe-west3`, правила
> опубликованы, аккаунт для входа создан. Раздел ниже — если нужно повторить всё
> с нуля или подключить свой проект.

Нужен, чтобы данные не потерялись при очистке браузера и были доступны на iPhone и Android.
Firebase бесплатного тарифа (Spark) здесь более чем достаточно: один пользователь, несколько
килобайт данных.

### 3.1. Создать проект

1. Откройте <https://console.firebase.google.com/> и войдите в Google-аккаунт.
2. **Add project / Создать проект** → название, например `vika-cycle`.
3. Google Analytics можно **отключить** — он не нужен. Нажмите **Create project**.

### 3.2. Включить вход по e-mail и паролю

1. Слева: **Build → Authentication** → **Get started**.
2. Вкладка **Sign-in method** → **Email/Password** → включите первый переключатель
   (**Email link / passwordless не нужен**) → **Save**.
3. Вкладка **Users** → **Add user** → e-mail (например `vika@example.com`) и пароль
   (минимум 6 символов). Запомните их — это вход в приложении.
   *Регистрацию из приложения лучше не включать: аккаунт ровно один, ваш.*

### 3.3. Создать базу Firestore

1. Слева: **Build → Firestore Database** → **Create database**.
2. Выберите **Production mode** (правила зададим ниже) → регион, ближайший к вам
   (например `europe-west3`) → **Enable**.

### 3.4. Правила безопасности (важно!)

Вкладка **Rules** — вставьте и нажмите **Publish**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/app/{docId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

Теперь каждый видит и меняет **только свои** данные. Чужой человек с вашим конфигом
не прочитает дневник: для чтения нужен вход под вашим аккаунтом.

### 3.5. Получить конфиг

1. Шестерёнка **Project settings** → вкладка **General**.
2. Прокрутите к **Your apps** → нажмите **`</>`** (Web).
3. Придумайте nickname (например `vika-pwa`), **Firebase Hosting не включайте** → **Register app**.
4. Скопируйте объект `firebaseConfig` — он выглядит так:

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "vika-cycle.firebaseapp.com",
  projectId: "vika-cycle",
  storageBucket: "vika-cycle.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef123456"
};
```

### 3.6. Вставить конфиг в код

Откройте `js/firebase.js` и замените пустые строки в самом верху:

```js
export const FIREBASE_CONFIG = {
  apiKey: "AIzaSy...",
  authDomain: "vika-cycle.firebaseapp.com",
  projectId: "vika-cycle",
  storageBucket: "vika-cycle.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef123456",
};
```

Всё. После перезагрузки в **Настройки → Синхронизация** появится форма входа.
Введите e-mail и пароль из шага 3.2 — данные уедут в облако и подтянутся на других устройствах.

> Если `apiKey` пустой, приложение работает в **локальном режиме** и ничего никуда не отправляет.
> Это нормальный сценарий, а не ошибка.

### 3.7. Если что-то не так

| Симптом | Причина и решение |
|---|---|
| «Неверный e-mail или пароль» | Пользователь создан в Authentication → Users? Пароль ≥ 6 символов |
| «В Firebase не включён вход по e-mail/паролю» | Authentication → Sign-in method → Email/Password → Enable |
| `auth/unauthorized-domain` | Authentication → Settings → **Authorized domains** → добавьте `ваш-логин.github.io` |
| «Нет сети» | Проверьте интернет; офлайн данные всё равно сохраняются локально |
| `Missing or insufficient permissions` | Не опубликованы правила из шага 3.4 |

## 4. GitHub Pages за 3 минуты

> **В этом проекте уже сделано:** репозиторий <https://github.com/nl4rvr/vika>,
> Pages включён, сайт живёт по адресу **<https://nl4rvr.github.io/vika/>**.
> Раздел ниже — если нужно повторить с нуля.

1. Создайте **публичный** репозиторий, например `vika`:
   <https://github.com/new>.
2. Загрузите файлы. Через сайт: **Add file → Upload files**, перетащите **всё содержимое папки**
   (не саму папку), включая `.nojekyll`, `icons/`, `js/`, `data/`. Нажмите **Commit changes**.

   Через терминал:

   ```bash
   cd путь/к/проекту
   git init
   git add .
   git commit -m "Vika PWA"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/vika.git
   git push -u origin main
   ```

3. В репозитории: **Settings → Pages**.
   - **Source**: `Deploy from a branch`
   - **Branch**: `main`, папка `/ (root)`
   - **Save**
4. Через 30–60 секунд сайт будет здесь:

   ```
   https://ВАШ_ЛОГИН.github.io/vika/
   ```

> **Папка `tools/`** нужна только для разработки. Её можно не загружать — приложение от неё не зависит.
> В проекте также может лежать папка `report/` с посторонними материалами — к приложению она
> отношения не имеет, её тоже можно не загружать.

**Если картинки или стили не грузятся:** проверьте, что загрузились папки `js/`, `data/`, `icons/`
с сохранением структуры. Все пути в проекте относительные (`./`), поэтому подпапка
`/vika/` работает без правок.

**Обновление версии.** После правок поднимите версию в двух местах — `PWA_VERSION` в
`js/pwa.js` и `VERSION` в `sw.js` (значения должны совпадать, например `vika-v1.4.0`) — и
закоммитьте. Иначе телефон может показывать старую версию из кэша.

## 6. Как пользоваться

### Цикл

- **Начались месячные** — одна кнопка на главном экране.
- **Закончились** — та же кнопка меняет подпись, пока запись открыта.
- **Детали дня** — выделения (скудные/обычные/обильные), симптомы, заметка.
- **Календарь** — нажмите любой день: можно начать/закончить месячные, отметить симптомы,
  перейти к мигрени этого дня.
- **Средняя длина цикла и менструации** считается по вашим записям (взвешенно по последним 6 циклам,
  с отбрасыванием выбросов). Значения из настроек — только запасные, пока истории мало.
- **Фазы**: менструация → фолликулярная → овуляция → лютеиновая. Границы пересчитываются
  от длины цикла (овуляция ≈ за 14 дней до следующих месячных).
- **Фертильность** показывается нейтрально: пик / повышенная / низкая + пояснение.
  Это информационная оценка, **не метод контрацепции**.

### Мигрени

- Нижняя панель → **Мигрени** (или кнопка на главном экране).
- Нажмите день в календаре:
  - **Не болела / Болела** + интенсивность (слабая, средняя, сильная);
  - препараты-чипы: **Эксенза — 1 пшик**, **Эксенза — 2 пшика**, **Нурофен**,
    **Ничего не принимала** (можно несколько);
  - заметка + быстрые теги (недосып, погода, стресс…).
- В календаре дни с болью подсвечены по интенсивности, под числом — точки принятых препаратов
  (лавандовая — Эксенза, зелёная — Нурофен).
- Статистика месяца: дней с болью, **пшиков Эксензы**, приёмов Нурофена.
- Если Эксенза используется чаще 2–3 дней в неделю, приложение мягко предложит обсудить
  профилактику с неврологом.

### Настройки

- Имя, длина цикла, длительность менструации (запасные значения).
- **PIN-код** (4 цифры, хранится как SHA-256-хеш только на устройстве) и автоблокировка.
- **Экспорт/импорт JSON** — резервная копия без облака.
- **Очистить всё** — удаляет историю с устройства.
- **Синхронизация** — вход в Firebase (появляется после вставки конфига).

### Советы

557 рекомендаций, распределённых по 4 фазам и категориям (питание, тепло, вода, сон, кожа,
уход, гигиена, эмоции, «вдвоём», работа, наблюдения, профилактика…). Без советов про
физические тренировки и без тем про друзей, родителей и бывших: из близких упоминается
только Кисунчик. На главном экране — «Рекомендация дня», которая меняется каждый день
детерминированно (один и тот же день = один и тот же совет), плюс кнопка «Ещё совет»
и полная библиотека с фильтрами по фазе и категории.

## 7. Приватность и данные

- По умолчанию **всё хранится в `localStorage`** вашего браузера. Никаких запросов наружу.
- PIN не шифрует базу, а закрывает вход в интерфейс. Он хранится как хеш и не отправляется в сеть.
- С подключённым Firebase данные лежат в `users/{uid}/app/state` и доступны только владельцу
  аккаунта (правила из шага 3.4).
- Экспорт JSON — единственная полная резервная копия. Делайте её перед очисткой браузера.
- Приложение не собирает аналитику, не показывает рекламу и не имеет чатов.

## 8. Медицинская оговорка

Приложение — личный дневник, а не медицинский прибор. Прогнозы цикла и фертильности
рассчитаны по средним значениям и могут смещаться; они **не заменяют** контрацепцию
и консультацию врача. При сильной боли, обильных кровотечениях, задержке более 7–10 дней
или изменении характера приступов обратитесь к специалисту.

## 9. Технические детали

**Service worker** (`sw.js`):
- навигация — `network-first` с фолбэком на `index.html` (офлайн-запуск);
- свои файлы — `stale-while-revalidate` (мгновенно из кэша, обновление в фоне);
- Firebase CDN — `network-first` с кэшем (не ломает офлайн).

Оболочку кэширует сама страница (`precacheFromPage` в `js/pwa.js`) — это надёжнее, чем
`install` в service worker, и одинаково работает во всех браузерах. SW отвечает за стратегии.

**Версионирование кэша.** `PWA_VERSION` в `js/pwa.js` и `VERSION` в `sw.js` — одинаковые
значения; при изменении старые кэши удаляются в `activate`.

**Структура состояния** (`localStorage` → ключ `vika.cycle.v1`):

```js
{
  version: 1,
  profile: { name, cycleLength, periodLength, tipsEnabled, lockEnabled, lockTimeout },
  periods: [{ id, start: "YYYY-MM-DD", end: "YYYY-MM-DD" | null, note }],
  days:    { "YYYY-MM-DD": { flow, symptoms: [], note } },
  migraines: { "YYYY-MM-DD": { pain: 0|1|2|3, meds: [], note } },
  updatedAt: "ISO"
}
```

**Слияние с облаком** — по `id` записей и по датам дней: объединяются симптомы, берётся
более полная запись о месячных, максимальная интенсивность мигрени. Конфликты не теряют данные.

**Добавить свои советы.** Откройте `data/tips/<фаза>.js` и добавьте строку:

```js
['Питание', 'Заголовок', 'Короткий текст совета в 1–2 предложения.'],
```

Формат: `[категория, заголовок, текст]`. Ничего больше менять не нужно — библиотека,
счётчики и фильтры подхватят запись автоматически.

## 10. Частые вопросы

**Нужен ли Firebase?**
Нет. Без конфига приложение полностью рабочее и офлайн. Firebase — только чтобы данные
пережили очистку браузера и синхронизировались между iPhone и ноутбуком.

**Почему не работает, если открыть `index.html` двойным щелчком?**
Браузер блокирует ES-модули на `file://`. Используйте локальный сервер (раздел 2)
или GitHub Pages (раздел 4).

**Обновил код, а телефон показывает старое.**
Поднимите версию в `js/pwa.js` и `sw.js`, задеплойте, закройте приложение полностью и
откройте снова. На iOS иногда нужно удалить иконку с экрана «Домой» и добавить заново.

**Можно ли пользоваться вдвоём?**
Архитектура рассчитана на одного пользователя (одна коллекция на аккаунт).
Для второй персоны сделайте копию проекта и второй аккаунт Firebase.

**Как сменить имя?**
Настройки → Профиль → Имя. Оно подставляется в приветствие и на экран PIN.
